# Заметки по Git

## Сравнение команд

- `git log` показывает историю коммитов: их сообщения и порядок.
- `git diff` сравнивает содержимое двух состояний файлов. Здесь он показал замену сложения на умножение.
- `git show` показывает сведения и изменения одного выбранного коммита. Предыдущий коммит содержал этап с вычитанием.

## Поиск и строки файла

- `git log -S"def"` ищет коммиты, в которых менялось количество текста `def` в файле. Результат пустой, потому что в `calc.py` этого текста нет.
- `git blame` показывает, в каком коммите последний раз менялась каждая строка. Первые две строки относятся к коммиту со сложением, третья — к коммиту с умножением.

## Восстановление файла

- `git restore lab03/calc.py` берёт файл из индекса. В упражнении индекс совпадал с последним коммитом, поэтому вернулась версия с умножением.
- `git restore --source=HEAD~2 lab03/calc.py` подставляет в рабочий файл более старую версию, но не передвигает ветку и не создаёт коммит.
- Перед восстановлением полезно посмотреть `git status` и `git diff`: незакоммиченные изменения рабочего файла могут быть потеряны.

## Отмена коммита

- `git revert` создаёт новый коммит, который отменяет изменения выбранного коммита. Исходный коммит остаётся в истории.
- `git reset --hard` передвигает ветку к другому коммиту и приводит рабочие файлы к его состоянию. Незакоммиченные изменения могут быть потеряны.
- Для отмены опубликованного изменения безопаснее использовать `revert`: он сохраняет историю и добавляет в неё коммит отмены.

## Тег и ветка

- Тег обычно закреплён за конкретным коммитом и служит меткой версии.
- Ветка — это указатель на линию работы; с новыми коммитами она перемещается.
